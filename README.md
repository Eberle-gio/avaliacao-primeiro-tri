# Avaliação Prática — Scrum, Kanban, Git e Gerenciamento de Configuração

## Objetivo

Esta atividade tem como objetivo avaliar conhecimentos relacionados a:

- Scrum;
- Kanban;
- Gestão de backlog;
- Histórias de usuário;
- Git e GitHub;
- Branches e commits;
- Gerenciamento de configuração;
- Organização do desenvolvimento de software.

A avaliação será realizada utilizando Git, GitHub e Markdown.

---

# Regras Gerais

Cada estudante deverá:

- clonar o repositório;
- criar uma branch individual;
- responder a avaliação teórica em Markdown;
- criar um quadro Kanban na organização do GitHub;
- criar épico, histórias, tarefas e critérios de aceitação;
- realizar commits durante as respostas - um para cada pergunta;
- enviar as alterações ao GitHub.

As tarefas não precisam ser realizadas em ordem sequencial.

---

# Branch Individual

Cada aluno deverá criar uma branch individual a partir da branch `main`.

## Padrão de Nome

```text
avaliacao-nome-sobrenome
```

Exemplo:

```text
avaliacao-marcelo-terenciani
```

---

# Quadro Kanban

Cada estudante deverá criar um quadro Kanban dentro da organização do GitHub compartilhada previamente.

## Nome do Quadro

O quadro deverá possuir o nome completo do estudante.

# Épico

Cada estudante deverá criar:

- 1 épico relacionado ao escopo recebido.

O épico deverá possuir:

- objetivo;
- descrição;
- critérios de aceitação;
- histórias relacionadas.

---

# Histórias de Usuário

O épico deverá conter:

- 3 histórias de usuário.
- no mínimo 4 tarefas;
- no mínimo 3 critérios de aceitação;
- critérios preferencialmente descritos como cenários.



# Avaliação Teórica

1. Faça uma cópia do arquivo `avaliacao.md`;
2. Renomeie para:

```text
respostas-nome-sobrenome.md
```

Exemplo:

```text
respostas-marcelo-terenciani
```


3. Responda todas as questões diretamente no arquivo Markdown avaliacao-nome-sobrenome.md.

---

# Commits

Os commits deverão seguir um padrão de nomenclatura.

## Estrutura

```text
tipo(escopo): descrição
```

---

# Entrega

A entrega será considerada somente quando:

- a branch estiver enviada para o GitHub;
- os arquivos estiverem preenchidos;
- o quadro Kanban estiver configurado;
- as histórias e tarefas estiverem cadastradas.

---

# Observações

- Não altere a branch `main`;
- Não exclua arquivos do repositório;
- Utilize commits organizados;
- Histórias genéricas ou incompletas terão desconto;
- Organização e clareza serão avaliadas;
